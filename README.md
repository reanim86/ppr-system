# Система ППР — C3Solutions

Веб-приложение для учёта планово-предупредительных ремонтов (ППР) оборудования производственной компании C3Solutions.

Система хранит график планово-предупредительных ремонтов по каждой единице оборудования, в день наступления срока уведомляет инженера, позволяет отмечать выполнение работ (полностью или частично, с процентом и комментарием), ведёт полную историю и формирует отчёт в Excel. Доступ — через браузер по локальной сети: инженер вносит данные, руководитель просматривает их в режиме «только чтение».

## Возможности

- **Оборудование** — добавление, изменение, удаление единиц оборудования (название, модель, мощность, цех, примечания).
- **График ППР** — работы по каждой единице оборудования с периодичностью (в днях), плановым временем выполнения (в часах) и датой следующего выполнения.
- **Отметка выполнения** — кнопка «Выполнено», процент 0–100% и комментарий:
  - процент — это **текущий суммарный уровень готовности** работы на дату отметки (снимок состояния), а не прибавка; записи **не суммируются**;
  - при отметке **100%** работа закрывается, и система сама считает следующую дату: `max(сегодня, срок) + периодичность`;
  - при частичном выполнении (например, 50%) работа остаётся в статусе «сегодня/просрочено» до полного закрытия.
- **Уведомления** — при наступлении срока:
  - красный баннер «Просрочено / на сегодня»;
  - звуковой сигнал (Web Audio API) и системное уведомление браузера;
  - счётчик в заголовке вкладки, например `(3) Система ППР`.
- **История выполнения** — полный журнал отметок: по каждой работе отдельно или по всем работам сразу, с указанием, кто сделал запись (инженер или руководитель).
- **Экспорт в Excel** — кнопка в шапке формирует `Отчет_ППР_<дата>.xlsx` (4 листа: Сводка, Оборудование, График ППР, История выполнения).
- **Доступ** — инженер и руководитель имеют полный доступ; роль «просмотр» (viewer) сохранена в системе для будущего использования.
- **Резервное копирование** — ежедневный бэкап БД (на Ubuntu — автоматически по cron).

## Стек и архитектура

| Компонент | Технология |
|---|---|
| Сервер | Python 3.10+, FastAPI, Uvicorn |
| База данных | SQLite (файл `ppr.db`, один файл = вся система) |
| Веб-интерфейс | HTML + CSS + JavaScript (без фреймворков, отдаётся тем же сервером) |
| Экспорт | openpyxl |
| Развёртывание на сервере | systemd + cron |

Схема: **браузер инженера** и **браузер руководителя** → HTTP → **FastAPI-сервер** (Ubuntu или ПК в сети) → **SQLite**.

> Пользователи не хранят данные локально — они просто открывают веб-страницу по адресу сервера.

## Требования

- Python **3.10+** (для Ubuntu и Windows).
- Для серверного развёртывания: ПК с Ubuntu (LTS), постоянно включённый, в локальной сети.

## Установка на Ubuntu (рекомендуется)

Сервер ставят один раз на постоянно включённый ПК/VM в сети. Инженер и руководитель дальше работают через браузер.

1. Скопировать папку проекта на сервер, например в `~/ppr-system`.
2. Запустить установку:

   ```bash
   cd ppr-system
   sudo ./deploy.sh
   ```

   Скрипт: ставит Python и зависимости, создаёт пользователя `ppr`, копирует приложение в `/opt/ppr-system`, регистрирует **systemd-сервис `ppr`** (автозапуск при загрузке, перезапуск при сбое) и настраивает ежедневный бэкап БД.

3. Открыть в браузере:
   - на сервере: `http://localhost:8000`
   - с других ПК сети: `http://<IP-сервера>:8000` (IP подскажет скрипт, также `hostname -I`)

4. Если включён брандмауэр `ufw`, открыть порт:

   ```bash
   sudo ufw allow 8000/tcp
   ```

Полезные команды:

```bash
systemctl status ppr      # статус сервиса
journalctl -u ppr -f      # логи
systemctl restart ppr     # перезапуск
```

## Установка на Windows (локально / для разработки)

Работает для локального запуска на одном ПК (например, для проверки).

```bat
setup.bat          :: установить зависимости (один раз)
run_server.bat     :: запустить сервер
```

Затем открыть `http://localhost:8000`. Для доступа руководителя с другого ПК сети — открыть `http://<IP-компьютера>:8000`.

## Как пользоваться

1. **Вкладка «Оборудование»** — добавьте оборудование.
2. **Вкладка «График ППР»** — добавьте работы: оборудование, название, описание, периодичность в днях (например, 90 = раз в квартал), плановое время выполнения в часах и дату следующего выполнения.
3. **Вкладка «Сегодня»** — карточки статистики и списки «Просрочено / на сегодня» и «Ближайшие (7 дней)». Здесь же кнопка **«Выполнено»**: процент и комментарий.
4. **Вкладка «История»** — журнал отметок: по умолчанию показывается по всем работам сразу (с колонками «Оборудование» и «Работа»), либо выберите конкретную работу в списке.
5. **Экспорт в Excel** — кнопка в шапке, доступна всем ролям.

### Как работает процент выполнения

Процент — это **текущая суммарная готовность работы** на дату отметки (снимок состояния), а **не прибавка**. Отметки **не складываются** между собой.

Пример — работа «Замена масла» на оборудовании «Токарный станок Т-1»:

| Отметка | Что вводим | Результат |
|---|---|---|
| 1-я | 50% | запись «50%»; работа остаётся открытой (в списке «сегодня/просрочено») |
| 2-я | 100% | запись «100%»; работа **закрывается**, следующая дата сдвигается на периодичность |

**Важно:** две отметки по 50% **не** дают в сумме 100% — при каждой отметке указывайте **текущий итоговый процент** (сколько сделано всего на этот момент). Чтобы закрыть работу, последняя отметка должна быть **100%**.

В истории («История») сохраняются все отметки — как отдельные фиксации прогресса.

## Уведомления

Система опрашивает сервер каждые 30 секунд **для всех пользователей** — и инженер, и руководитель получают уведомления одинаково (у каждого в своём браузере). Когда появляется работа со сроком «сегодня» или просроченная:

- вкладка браузера **должна быть открыта** (свёрнута можно);
- показывается красный баннер и список задач;
- звучит тройной сигнал (после первого клика по странице — требование браузеров об автозапуске звука);
- в заголовке вкладки появляется счётчик `(N) Система ППР`;
- если браузер разрешил системные уведомления — появляется всплывающее уведомление.

## Экспорт в Excel

Файл `Отчет_ППР_ГГГГ-ММ-ДД.xlsx`, листы:

1. **Сводка** — дата отчёта, количество оборудования/работ, просрочено, на сегодня, ближайшие 7 дней, всего выполнений.
2. **Оборудование** — модели, мощность, расположение, количество работ по каждому.
3. **График ППР** — оборудование, модель, работа, периодичность, плановое время, следующий срок, статус (Просрочено / Сегодня / Скоро / В графике), дата, результат и автор последнего выполнения.
4. **История выполнения** — все отметки: дата, оборудование, работа, кто выполнил, процент, комментарий.

## Годовой план работ («Годовой план»)

Кнопка **«Годовой план»** в шапке формирует файл `Годовой_план_ППР_ГГГГ.xlsx` за выбранный год (запрашивается год, по умолчанию — текущий). Три листа:

1. **Год** — шапка бланка (УТВЕРЖДАЮ, наименование организации, год) и таблица:
   - оборудование **сгруппировано по «Расположению»**;
   - **«Ед.изм.»** — параметр «Мощность» оборудования;
   - **«Месяц проведения ремонта»** (I–XII) — символ **«Х»**, если в этом месяце по оборудованию запланирован ремонт;
   - **«Трудоемкость, чел*час.»** — суммарные плановые часы за год (плановое время работы × число её выполнений в году).
2. **Год по дням** — оборудование (сгруппировано по «Расположению») × каждый день года:
   - в ячейке — **количество часов** работ этого оборудования на конкретный день (из параметра «План, ч» в графике ППР);
   - между месяцами — **разделительные столбцы** (залиты цветом);
   - внизу — строка **«Итого, ч»** с суммарными часами по каждому дню.
3. **Диаграмма Ганта** — по оси Y — оборудование, по оси X — дни года; каждая работа с плановым временем — полоса в день выполнения (длина полосы = длительность в днях, часы/24). Работы без планового времени на диаграмму не попадают; легенда скрыта. **Зум по месяцу** — в Excel: «Формат оси → Границы» (задать минимум/максимум).

Даты выполнений вычисляются от «следующего срока» шагами по периодичности (вперёд и назад в пределах года).

## Резервное копирование

Вся система — это один файл БД `ppr.db`. Достаточно копировать его.

- **Ubuntu**: автоматически каждый день в 02:00, копии в `/var/backups/ppr/` (хранятся 30 штук). Копирование через SQLite API, безопасно при работающем сервере.
- **Windows/вручную**: просто скопируйте файл `ppr.db` рядом с приложением, пока сервер остановлен (или используйте системный бэкап).

## API (кратко)

Авторизация — заголовок `Authorization: Bearer <token>` (токен выдаёт `POST /api/login`).

| Метод | Путь | Роль | Описание |
|---|---|---|---|
| POST | `/api/login` | все | вход, получение токена |
| GET | `/api/me` | все | текущий пользователь |
| POST | `/api/password` | все | смена своего пароля |
| GET | `/api/machines` | все | список оборудования |
| POST | `/api/machines` | инженер/рук. | добавить оборудование |
| PUT/DELETE | `/api/machines/{id}` | инженер/рук. | изменить/удалить оборудование |
| GET | `/api/tasks` | все | график ППР |
| POST | `/api/tasks` | инженер/рук. | добавить работу |
| PUT/DELETE | `/api/tasks/{id}` | инженер/рук. | изменить/удалить работу |
| GET | `/api/due` | все | просрочено / сегодня / ближайшие 7 дней |
| POST | `/api/tasks/{id}/complete` | инженер/рук. | отметить выполнение (percent, comment) |
| GET | `/api/tasks/{id}/logs` | все | история выполнения работы |
| GET | `/api/stats` | все | карточки статистики |
| GET | `/api/export.xlsx` | все | отчёт в Excel |

## Устранение неполадок

- **Сайт не открывается с ПК руководителя** — проверьте, что сервер запущен, ПК в одной сети, порт `8000` открыт брандмауэром.
- **Нет звука при уведомлении** — сначала кликните по странице (браузеры блокируют звук до первого взаимодействия), проверьте громкость системы.
- **Забыли пароль** — пересоздайте БД (удалите `ppr.db` и перезапустите сервис — появятся пароли по умолчанию) либо сбросьте через Python: `python -c "from app.db import hash_password, execute; execute('UPDATE users SET password_hash=? WHERE username=?', (hash_password('новый_пароль','engineer'), 'engineer'))"`.
- **Порт 8000 занят** — задайте другой порт переменной окружения `PPR_PORT` (Ubuntu) или правкой `run_server.bat` (Windows).
